Example: Ndiédieng (live at /ndiedieng)#

A full use case for the commune of Ndiédieng (Kaolack, Senegal), and the website's live demo: kalangu.utachi.website/ndiedieng. Code and French README in examples/ndiedieng.

  • Prototype: USSD *123# menus (breakdowns, births, deaths, follow-up, free message), free SMS and voice messages sorted by category and urgency, the town hall's reports, SMS back to the chief, the territorial assistant with the data behind each answer (rules, or Gemini on the server)
  • Online at /ndiedieng, running entirely in the browser (sql.js); CI checks the published page is built from source (check:web)
  • Three phones true to their systems: keypad phone, Android (Material 3), iPhone (iOS)
  • Reports: open, edit, create and delete from the dashboard; the dashboard fits the screen without scrolling
  • The assistant on its own page (/ndiedieng/assistant/), with an orb to tap and speak; answers read aloud or written
  • Voice: a clear message instead of a hang where a browser offers dictation without running it; live waveform and glow
  • The in-browser demo kept in IndexedDB, shared by both pages; "start over" in Help
  • Undo after deleting a report, CSV export of the list, and a quick search (Ctrl/Cmd + K) over reports, villages and actions
  • Linked from the README, the docs overview and the landing page
  • Gemini on the website: a serverless function (/api/ndiedieng/gemini, built from src/geminiFunction.ts) holds GEMINI_API_KEY; fixed tasks only, limited per visitor, the rules whenever it fails
  • Confirm the function answers on the live site: it did on 20 Nov 2026 (questions, greetings and the spoken answers)

Design review: open questions (design doc §12), settled 17 Nov 2026#

Decisions are recorded under "Decisions" in §12. Question 1 stays unverified until a real operator confirms 98 is not intercepted (see the checklist above).

  • 1. Navigation numbers: use 98 (More) ourselves, given telcos reserve it for auto-pagination?
  • 2. Unsafe-character policy on USSD screens: strip + warn vs strict mode
  • 3. Legacy vs new bulk SMS endpoint (legacy recommended until its sandbox ships)
  • 4. SMS split cap (proposed max 4 segments, never silent truncation)
  • 5. Callback authenticity: document path-secret/IP-allowlist mitigations (no signing exists to implement)
  • 6. Re-notice vs block-screen when a user redials during a pending deferral
  • 7. enqueue default on SMS send (proposed: omit unless configured)
